# Запись в индекс подтверждена, курсор ещё не сохранён

Инвариант: PostgreSQL хранит каталог и журнал изменений; индексатор может
повторить уже применённую пачку без потери новой версии или восстановления
удалённого товара. OpenSearch является восстанавливаемой поисковой проекцией.

```bash
export COMPOSE_PROJECT_NAME=proof-searchharbor-demo
uv sync --extra dev --frozen
make up
make recovery
docker compose --profile test down -v
```

Нужны Docker Compose, Python 3.12 и uv; порт 8220 должен быть свободен.
Первый запуск загружает зафиксированные публичные ONNX-модели. Стенд отдельный;
последняя команда удаляет его данные и кэш моделей.

[Recovery](../scripts/recovery_smoke.py) увеличивает задержку worker после bulk.
Через realtime GET он убеждается, что документ уже есть в OpenSearch, и отдельно
читает курсор из PostgreSQL: тот ещё меньше версии события. Только после этого
worker получает SIGKILL. Перезапуск с обычной задержкой приводит к повтору пачки
и догоняет каталог. JSON сохраняет `cursor_before_kill`, `event_replayed` и `passed`.

В том же запуске проверяются остановка OpenSearch и rebuild параллельно поиску:
изменение каталога сохраняется при недоступной проекции, а после восстановления
новая цена остаётся и удалённый товар не возвращается. Скрипт очищает временные
товары и возвращает worker в обычный режим. Эти проверки уже входят в CI.
Локальный результат этапа D: [verification-stage-d.json](verification-stage-d.json).

Для интервью покажите документ в индексе, отстающий курсор, реальный SIGKILL
и восстановление. Версия документа и tombstone делают повтор безопасным;
сам факт доставки пачки этого не гарантирует. Один шард без реплик не даёт HA.
Сценарий подтверждает корректность восстановления, а не качество модели,
независимость ML-бенчмарка или производительность под нагрузкой.
