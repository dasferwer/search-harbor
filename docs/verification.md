# Проверенный результат

Локальный прогон 13 сентября 2026 года: macOS, Docker Desktop, Python 3.12 в контейнерах, PostgreSQL 17, OpenSearch 3.2.0. Это снимок выполненных проверок, а не обещание текущей доступности стенда.

| Проверка | Результат |
| --- | --- |
| `make check` | Ruff и форматирование прошли. |
| `make test` | 70 тестов прошли за 3,30 с: 61 интеграционный тест на настоящих PostgreSQL/OpenSearch и 9 тестов метрик и протокола оценки. |
| `make up` | Миграция и загрузка моделей завершились; API, worker, PostgreSQL и OpenSearch healthy. |
| `make smoke` | Все четыре режима с настоящими моделями, авторизация, повтор запроса, конфликт ключа, изменение цены и удаление. |
| `make recovery` | Остановка OpenSearch, SIGKILL worker после bulk, перестройка одновременно с поиском и изменениями каталога. |
| `make evaluate` | 12 запросов dev и 24 запроса test, по три повтора в четырёх режимах: 432 измеренных запроса и 8 прогревочных. |

Интеграционные тесты используют детерминированные векторы-заглушки, чтобы проверять версии, фильтры и восстановление независимо от скачивания весов. Smoke и оценка работают с готовыми BGE и MiniLM на CPU.

## Что произошло при сбоях

При остановленном OpenSearch изменение товара сохранилось в PostgreSQL, чтение товара работало, поиск и readiness вернули 503. После запуска OpenSearch worker догнал журнал без ручной правки курсора.

Перед SIGKILL документ уже находился в OpenSearch через realtime GET, а курсор PostgreSQL оставался на 3004, перед событием 3005. После запуска worker повторил пачку и догнал каталог. Проверка явно дождалась этого промежутка, а не полагалась только на задержку по таймеру.

Во время rebuild выполнено 16 успешных поисковых запросов без ошибок: наблюдались ответы как от старого, так и от нового поколения. Изменённая цена сохранилась в новом индексе, удалённый товар не вернулся, старый индекс остался доступен для уже начавшихся запросов.

Отдельные тесты удаляют активный и частично построенный индексы. Потерянный активный индекс восстанавливается через новую сборку; для потерянного строящегося индекса сначала сохраняется нулевой курсор, затем повторяется история. Также проверены запоздавшее событие после tombstone, конкурирующие процессы worker, частичный bulk и несовпадение модели.

## Итоговое состояние

После удаления временных товаров осталось 3 000 живых SKU, 3 008 событий и активное поколение с курсором 3 008 без ошибки. Повторный seed сохранил эти числа и историю. Тестовые контейнеры остановлены. Аварийная задержка worker возвращена в 0.

API и worker запускаются от UID 999, без pytest и Ruff в runtime. Хеши всех Python-файлов установленного пакета в обоих контейнерах совпали с исходниками. На хост опубликован только `127.0.0.1:8220`; PostgreSQL и OpenSearch доступны в сети Compose.
